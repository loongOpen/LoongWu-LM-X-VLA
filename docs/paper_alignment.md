### 方差传播

按论文的 log-variance 定义，单步独立噪声项为 `dt² * exp(log_var)`；
论文还包含用 Jacobian 与 Hutchinson 估计近似的协方差项。
当前动作头使用 `sum((exp(log_var) * dt)²)`，未加入该协方差项。
因此，现有 `action_uncertainty` / `uncertainty_score` 不应直接解释为已复现的论文终端方差，
也不能沿用论文的告警阈值。来源：[论文公式 (12)–(14)](https://arxiv.org/html/2608.25757v3#S2.SS6)。

本次保留现有推理行为。后续公式调整需要先确认 checkpoint 的输出参数化，
再用固定输入、初始噪声、逐步均值与方差参考结果进行回归。

## Python API 字段

[`LMXPolicy.get_action()`](../src/lm_x/policy.py) 返回 `(actions, info)`。
以下是已有 API，不新增名为 `rtg` 或 `etg` 的别名，也不改变模型权重键。

| 字段 | 当前含义 |
| --- | --- |
| `actions` | 按 checkpoint 动作组解码的实际动作片段 |
| `info["value_pred"]` | value 分支的标量预测；解释为进展需要核对训练标签与归一化定义 |
| `info["action_uncertainty"]` | 当前公式累计的辅助张量；未反归一化到各动作组的物理单位 |
| `info["uncertainty_score"]` | 上述张量在时间轴与动作维度上的均值，不是成功概率 |

辅助字段仅在模型返回有效结果时存在。客户端必须检查字段，不能假定每个兼容
checkpoint 都包含全部分支。
