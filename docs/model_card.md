# 龙悟LM-X 模型卡

本模型卡区分论文研究模型、当前仓库实现与运行验证三个层次。
论文依据为 [arXiv:2608.25757v3](https://arxiv.org/abs/2608.25757v3)；
运行时版本号不代表一组已经发布的模型权重。

## 模型定位

龙悟LM-X 面向可解释机器人操作，在动作生成之外预测 RTG、ETG 和动作不确定性，
分别用于观察任务进展、下一语义事件与局部动作可靠性。
论文的“可解释”指显式预测信号，而非自然语言推理解释或形式化安全保证。
来源：[论文 §2 与附录 A.4](https://arxiv.org/html/2608.25757v3#A1.SS4)。

适用场景是已有兼容 checkpoint 的推理研究、软件集成和部署验证。
实际可执行的任务、适配本体与泛化范围由使用的 checkpoint 及其数据和验证结果决定。

## 论文模型与当前实现

论文 §2.2 描述约 **6B** 参数的完整模型：Cosmos-Reason2-2B backbone，
RTG 专家及独立的事件/动作专家。摘要报告超过 **20,000 小时**的真实机器人轨迹，
其中包括超过 **1,000 小时**的失败轨迹。
这些是[论文报告](https://arxiv.org/abs/2608.25757v3)，不是本仓库发布的权重清单或数据资产。

下表仅描述当前运行时：

| 组成 | 当前实现 |
| --- | --- |
| 视觉语言 backbone | Qwen3-VL 路径；默认配置引用 Cosmos-Reason2-2B，可显式覆盖兼容资源路径 |
| 本体状态编码 | 按 checkpoint 投影映射选择的本体条件化编码器 |
| 动作生成 | 条件化动作头与流匹配积分，生成连续动作片段 |
| 动作解码 | 按 checkpoint 统计反归一化，并按动作表示配置处理相对/绝对动作 |
| 可选扩展 | value、uncertainty，是否启用由 checkpoint 配置决定 |

backbone 路径覆盖不会使任意视觉语言模型自动兼容；架构、特征维度、processor 和权重必须匹配。
具体 checkpoint 的参数量、分支配置与动作时域需要读取其配置和权重，
不能由论文参数或运行时默认值直接推断。运行时不统一声明推理控制频率。

当前 `value` 分支的隐状态参与动作条件；本开源运行时暂时不提供 keyframe（ETG）
推理代码。当前不确定性累计也未实现论文中的完整方差传播。
因此，本仓库尚不能声明完整复现论文模型或论文指标。
逐项配置、输出字段与差异见[论文对齐说明](paper_alignment.md)。

## 输入输出

| 数据 | 约定 |
| --- | --- |
| 图像 | 多个 RGB 流，`uint8 (B, T, H, W, 3)`；空间尺寸由图像预处理适配 |
| 状态 | `float32 (B, T, D)`；`D` 来自对应本体的归一化统计 |
| 指令 | `list[list[str]]`，每个 batch 样本一条指令 |
| 动作 | 按动作组返回的 `float32 (B, T_action, D_action)` 数组 |
| 辅助输出 | `info` 字典，内容取决于 checkpoint 启用分支 |

`get_io_spec()` 返回键、时间采样索引、数据类型与状态/动作维度，可经 JSON 或 ZeroMQ 原样传输。
本体标签必须同时被运行时识别，且存在于当前 checkpoint 的模态配置与投影映射中。

## 验证范围

CPU 测试验证软件行为：输入输出契约、元数据检查、预处理、动作积分、mock 加载和服务传输。
真实 checkpoint smoke 验证指定权重在指定设备上能完成一次合成输入推理。

当前运行时与具体 checkpoint 的任务成功率、泛化能力、时延、吞吐、显存占用和长时间稳定性需要单独测量。
本仓库不将合成输入、随机小模型或 mock 结果作为模型效果指标，也不提供未经实测的硬件矩阵。
请按[推理指南](inference.md#验证与复现)记录 checkpoint、运行环境与测试结果。

## 使用边界

运行时输出动作张量；机器人驱动、执行频率、动作限位、急停和故障恢复由应用系统负责。
状态/动作单位与坐标系依赖 checkpoint 的数据定义，不能仅凭数组维度推断。

`uncertainty_score` 是当前实现的辅助输出，未按论文公式完成对齐，
也无本仓库提供的校准证据；不得直接套用论文告警阈值或当作安全阈值。
随机动作采样可能使同一输入产生不同结果；设置随机种子也不承诺跨设备逐位一致。
